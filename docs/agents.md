# agents.md — AI agent guidelines for ax

## Project identity

**ax** is a semantic annotation layer where the DOM is the contract between a webpage and an agent interface. It compiles `ax-*` attributes into a tree-based DAG and executes lifecycle hooks the page promises.

## Source layout

| Path | Purpose |
|---|---|
| `src/index.js` | Single-file implementation (IIFE-wrapped, ~930 lines) |
| `docs/spec.md` | Full specification document |
| `README.md` | Developer-facing summary |
| `scripts/generate-golden.mjs` | Golden file generator for tests |
| `tests/` | Test files (Bun test + jsdom) |
| `tests/assets/*.html` | Full HTML documents with ax annotations |
| `tests/assets/*.dag.json` | Golden reference files (generated, never hand-written) |
| `dist/` | Built bundles (ax.js, ax.min.js) |

## Architecture

### IIFE pattern

`src/index.js` is wrapped in an IIFE to scope internals:

```js
const ax = (function () {
    "use strict";
    // ... all internal state and helpers ...
    return { scan, invoke, watch, unwatch, defineExtension, removeExtension, definePrimitive, config };
})();
export default ax;
```

- All internal state (`PRIMITIVE_KINDS`, `extensions`, `lastScan`, `elementToId`, etc.) is closure-scoped
- Only the return object leaks to module scope
- No `var`, `let`, `const` outside the IIFE (except JSDoc typedefs and the `export default ax` line)

### Compilation model (element-centric)

- One DOM element → one tree node with an array of `fn` entries
- `scan()` walks the DOM building an `InternalNode` tree, then serializes to `{ dag, nodes }`
- `<html>` is implicit root scope
- `ax-ctx` creates scope boundaries
- `ax-ignore` excludes subtrees entirely
- Non-ax elements are transparent — their ax-annotated children attach to the nearest ax ancestor

### Node shape

```js
// Internal (during walk)
{ id, el, fn, _parent, _children, scope, attrs }

// Serialized (in scan output)
{ id, parent, children, fn }
// No scope, no el, no internal fields
```

### Edit args from native HTML

ax derives edit field schemas from native HTML attributes, not custom `data-ax-*`:

- `type="email"` → `"email"`, `required` → `""` suffix, optional → `"?"` suffix
- Container elements (form, div) aggregate their descendants' field schemas
- Only input-like elements produce field-level args

### Hook evaluation (HTMX-style)

```js
new Function("ctx", `return (${raw})(ctx);`)
```

- Controlled by `ax.config.allowEval` (default `true`)
- Hook attribute names: `ax-onClick`, `ax-beforeClick`, `ax-afterClick` (camelCase after phase)
- Also accepts lowercased form (`ax-onclick`) since browsers normalize DOM attribute names
- `data-ax-onClick` / `data-ax-onclick` prefix forms also supported
- Dash-separated forms like `ax-on-click` are **not** supported

### Hook lifecycle phases

```
extension.beforeAction → before hook → on hook → after hook → extension.afterAction
                                    ↘ default behavior if no on-hook
```

- `before` can cancel via returning `false` or setting `ctx.canceled = true`
- `on` return value becomes `ctx.result`
- `after` executes regardless of cancellation
- Errors caught in hooks propagate to `ctx.error` and into invoke result

### Invoke result shape

```js
{ ok: true, result: "purchased" }
{ ok: false, canceled: true, error: "validation failed" }
{ ok: true, result: undefined }          // no on-hook, default behavior ran
{ ok: false, error: "No target element" } // argument errors
```

### Overload resolution

```js
ax.invoke(el, "click")               // 2-3 args → el is Element
ax.invoke("scope", el, "click")      // 4 args  → first arg is string scope
ax.invoke(el, "edit", { value: x })  // 3 args  → el is Element (no scope)
```

### DOM watch

`ax.watch()` sets up a `MutationObserver` on `document.documentElement`:

- Clears `lastScan` and `elementToId` WeakMap on any ax-attribute mutation or childList change
- The attributeFilter covers both camelCase and lowercase forms of all hook attributes
- `ax.unwatch()` disconnects the observer

## Test patterns

### File structure

Each asset HTML file in `tests/assets/` has:
1. A `.html` file — full `<!DOCTYPE html>` document with inline scripts exposing helpers to `window`
2. A `.dag.json` golden file — generated by `scripts/generate-golden.mjs`
3. A `tests/*.test.js` test file that loads the asset via jsdom

### Golden file testing

- Reference DAGs are generated from ax itself, never hand-written
- `bun run generate` regenerates all golden files
- Tests use a `normalizeDAG` helper that maps dynamic IDs (e.g., `ax-0-4kv8po`) to stable `$`-prefixed aliases derived from fn fingerprints
- Tests validate structural properties (dag shape, node count, fn contents) and hook lifecycle, not DOM page state

### Key testing principles

- **Test ax behavior, not page behavior**: verify invoke result shapes (`{ ok, canceled, result, error }`) and scan output structure
- **Do not query DOM for page state** — that tests the test setup, not the library
- **Extension hooks** should verify that `ctx` fields are populated correctly at each phase

### Common pitfalls

- **Realm isolation**: `new Function()` resolves globals in Bun's realm, not jsdom's. Hoist known function names from `dom.window` to `globalThis` in test setup.
- **Stale scan cache**: After clearing DOM between tests, `lastScan` may hold stale data. Tests rely on `elementToId` WeakMap check in `invoke()` to detect staleness.
- **Attribute normalization**: Browsers normalize `ax-onClick` to `ax-onclick` in the DOM. `readHooks()` checks both camelCase and lowercase forms.
- **MutationObserver realm error**: Must hoist `globalThis.MutationObserver = dom.window.MutationObserver`.

## Conventions

- **Hook naming**: `ax-onClick`, `ax-beforeClick`, `ax-afterClick` (camelCase after phase word)
- **`data-ax-*` prefix**: All `ax-*` attributes accept `data-ax-*` as alternative
- **No dash-separated hooks**: `ax-on-click`, `ax-before-view` are invalid
- **No ax-* equivalents for native HTML**: If `required` exists on the element, that's the contract — no `data-ax-validate`
- **Golden files are generated**: Run `bun run generate` after changing HTML assets, never hand-edit `.dag.json`

## Commands

```bash
bun test          # run all tests
bun run typecheck # TypeScript type checks
bun run build     # bundle dist/ax.js and dist/ax.min.js
bun run generate  # regenerate golden DAG files from HTML assets
```
